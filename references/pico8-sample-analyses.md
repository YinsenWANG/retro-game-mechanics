# 六个代表性卡带的源码设计简报

## 样本范围与方法

以下样本覆盖平台动作、射击、解谜、极简闪避、策略数字游戏和潜行 Roguelike。分析基于 2026-07-17 获取的、页面明确标注 **CC BY-NC-SA 4.0** 的卡带版本与作者页面；许可证允许的范围不等于允许商业复刻，使用者仍需遵守署名、非商业和相同方式共享条件。

本文件只总结设计和源码结构，不包含原始代码、图像、地图或音频。每项结论按 **[事实]、[源码观察]、[设计推断]** 区分。静态调用关系经过人工阅读核验，但不等同运行时追踪。

## 1. Celeste Classic 2

**来源**：[官方 BBS 页面](https://www.lexaloffle.com/bbs/?pid=celeste_classic_2)；作者 Maddy Thorson、Noel Berry、Lena Raine；页面卡带版本 `celeste_classic_2-5`；平台动作；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家在短关卡中攀登、收集草莓并追求更短时间和更少死亡。
- **[源码观察]** 基础输入是左右移动、跳跃和水平抓钩；抓钩可附着实体/地形、拉动可交互物或给玩家一个带动量的位移。
- **[源码观察]** 循环为“观察地形与可抓目标 → 跳跃/墙跳建立位置 → 抓钩改变运动关系 → 保持或转换动量 → 到达检查点/终点”。
- **[设计推断·高]** 抓钩同时是移动、互动和动量管理工具，因此少量按钮可以产生丰富路线表达。

### 状态、实体与物理

- **[源码观察]** 玩家状态至少包含正常、升降、弹板、抛出抓钩、附着加速、拉取物体、拾取、死亡和完成。
- **[源码观察]** 主要实体包括抓钩拾取、尖刺、雪球、弹板、桥、草莓、碎裂块、检查点和生成器。
- **[源码观察]** 碰撞依赖地图旗标与独立命中框；包含约 4 帧离地宽容和跳跃缓冲、可变跳高、墙跳及抓钩跳。
- **[源码观察]** 关卡用数据表组织，并把压缩关卡数据解压到用户 RAM；样本包含 8 个关卡/片段条目与不同相机模式。

### 难度、反馈与重试

- **[源码观察]** 难度主要通过空间组合、危险物和动作串联增长，而非提高敌人生命值。
- **[源码观察]** 死亡触发短冻结、屏幕震动和擦除转场，然后从检查点恢复；统计时间、死亡和草莓。
- **[设计推断·高]** 快速重试把高难动作从惩罚变成练习循环，反馈让玩家知道何时失去控制。

### 代码结构与关键关系

- **[源码观察]** `_init → load_level / reset`；`_update → player/object updates → collisions → camera/effects`；`_draw → map → objects → particles/UI`。
- **[源码观察]** 采用轻量原型/对象系统（对象创建、类型注册、更新和绘制方法）组织大量小实体；关键规则集中在玩家状态和碰撞辅助函数中。

### 机制作用

- **[设计推断·高]** 一个动作同时服务移动、物体互动和动量管理；速度与路线因此成为熟练度表达。快速失败—重试支持反复练习，关卡通过已有动作的新组合增加难度。

## 2. Shmup Pico-8

**来源**：[官方 BBS 页面](https://www.lexaloffle.com/bbs/?pid=shmuppico8)；作者 pareinjeanphilippe；卡带 `shmuppico8-0`；纵向射击；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家在屏幕下方移动、自动射击，清理多波敌人后挑战 Boss。
- **[源码观察]** 四向移动；按 X 后以约 0.20 秒间隔连续射击；初始 5 条生命。
- **[源码观察]** 循环为“移动对齐 → 自动/连续射击 → 避弹和拾取护盾 → 清波 → Boss → 结算”。
- **[设计推断·中]** 自动连续射击降低操作负担，把主要注意力留给位置判断。

### 状态、实体与碰撞

- **[源码观察]** 通过把 `_update` / `_draw` 指向菜单、游戏或结算函数来切换主状态。
- **[源码观察]** 实体列表包括玩家、两类普通敌人、Boss、双方子弹、护盾、星空、粒子和浮动分数。
- **[源码观察]** 多数碰撞是 8×8 AABB，Boss 使用更大区域；受伤后有约 40 帧无敌，护盾可抵消一次危险。

### 难度、奖励与重试

- **[源码观察]** 每轮从两类敌人中选择一种并随机生成 2–10 个；9 波后进入 200 生命 Boss。普通敌人和 Boss 命中产生分数、闪烁、粒子、音效和震动。
- **[源码观察]** `lvl` 记录波次，但普通波的速度、攻击模式和 Boss 参数没有显著随局数扩展；长期难度曲线较平。
- **[源码观察]** 最高分持久化；失败进入结算后重新开始。
- **[源码观察]** 页面描述护盾持续约 30 秒，而样本源码以 300 次绘制为阈值，在标称 30 FPS 下更接近 10 秒。这是作者说明与源码版本的可见差异。

### 代码结构与关键关系

- **[源码观察]** `_init → menu state`；`game_update → player/enemy/bullet/pickup updates → collisions → wave/boss state`；对应绘制函数按背景、实体、特效和 UI 分层。
- **[源码观察]** 结构以全局表和按类型的更新/绘制函数为主，简单直接，但规则、展示和状态切换耦合较多。

### 机制作用

- **[设计推断·中]** 连续射击降低了攻击操作负担，使移动和位置判断成为主要注意力对象；少量敌人类型、波次和 Boss 已能构成清晰的准备—释放节奏。
- **[源码观察]** 护盾用绘制次数计时，使其实际持续时间受帧行为影响；这是实现细节如何改变玩家感知规则的例子。

## 3. Lights Out

**来源**：[官方 BBS 页面](https://www.lexaloffle.com/bbs/?pid=jnk_lights)；作者 junkitself；卡带 `jnk_lights-3`；解谜；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家选择格子，使它和正交相邻格循环变化，目标是把棋盘全部清零。
- **[源码观察]** 棋盘是 8×7；移动光标并确认一个格子。初期为二态，达到第 19 级后变为三态循环。
- **[源码观察]** 循环为“观察局面 → 预测十字影响 → 选择格子 → 局部状态改变 → 继续消元 → 清盘或付分重开”。
- **[设计推断·高]** 单个动作的局部连锁非常清楚，但多个动作会形成全局线性/模运算结构，学习门槛低而推理空间大。

### 状态、生成与规则

- **[源码观察]** 菜单、游戏和结算同样通过回调替换表示。
- **[源码观察]** 谜题不是任意随机格局，而是从全零棋盘执行若干次合法按压生成，因而天然可解；空白结果会重生成。
- **[源码观察]** 难度参数按 `d = d + floor(sqrt(d))` 增长，控制生成时的操作次数；第 19 级引入三态是一次规则台阶。

### 奖励、失败与重试

- **[源码观察]** 没有传统死亡；重开会扣分并重置步数。得分综合关卡、难度、移动步数和重开惩罚，最高分持久化。
- **[设计推断·高]** 无死亡和保证可解降低了随机不公平感；计步/计分又让玩家愿意优化，而不仅满足于过关。

### 代码结构与关键关系

- **[源码观察]** 初始化棋盘与显示状态；按压函数集中处理中心及四邻居；关卡生成重复调用同一合法按压规则；完成检测驱动计分和下一关。
- **[源码观察]** 游戏规则集中、实体极少，最适合从“状态转移函数”和“生成器复用规则”两部分理解。

### 机制作用

- **[设计推断·高]** 用合法动作反向生成谜题保证了可解性；二态到三态的规则台阶扩展推理空间；没有传统死亡，把失败转化为效率和得分损失。

## 4. Rockets!

**来源**：[官方 BBS 帖](https://www.lexaloffle.com/bbs/?tid=47633)；作者 siddharthroy；卡带 `rockets-6`；双按钮极简动作；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家只用左右转向，让自动前进的载具躲避追踪导弹、收集硬币并生存得分。
- **[源码观察]** 追踪导弹从四周生成并平滑转向玩家；两个导弹相撞会同时消失、增加击毁数并生成硬币。
- **[源码观察]** 循环为“读取来袭提示 → 转向塑造追踪轨迹 → 诱导导弹互撞 → 折返收集奖励 → 在更多追踪物中继续生存”。
- **[设计推断·高]** 玩家没有直接攻击键；防御路线同时是间接进攻和资源生成，转向因此持续包含多目标权衡。

### 状态、碰撞与世界

- **[源码观察]** 玩家自动前进，镜头跟随一个可持续延伸的世界；多层地图/背景形成视差。
- **[源码观察]** 导弹之间、导弹与玩家、玩家与硬币使用距离/区域检测；玩家被导弹命中即结束。
- **[源码观察]** 生成前有边缘方向指示线和声音预告；导弹约每 50 次更新生成，场上上限约 5 个。

### 难度、奖励与重试

- **[源码观察]** 得分由生存时间、硬币和诱导击毁组成；爆炸、粒子、提示、音效和死亡文案强化事件。
- **[源码观察]** 解锁阈值 0/50/100/150/200 主要更换载具外观。生成间隔和上限没有明显长期收紧，难度更多来自同时存在的追踪关系。
- **[源码观察]** 一击失败后快速返回；最高分用于解锁展示。

### 代码结构与关键关系

- **[源码观察]** 更新顺序围绕玩家运动、相机、导弹寻迹、两两碰撞、硬币和粒子；绘制以世界层、实体、警告和 HUD 排列。
- **[源码观察]** 核心函数关系是“导弹寻迹 → 导弹两两检测 → 碰撞生成硬币/粒子 → 分数与解锁”。

### 机制作用

- **[设计推断·高]** 敌方追踪既是威胁，也是玩家可操纵的间接攻击系统；出生预告让风险可规划，极少输入仍能产生路线表达，而奖励出现在导弹相撞的位置又迫使玩家返回危险区域。

## 5. Skle

**来源**：[官方 BBS 页面](https://www.lexaloffle.com/bbs/?pid=skle)；作者 vteromero；卡带 `skle-0`；数字策略；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家从三个算术操作中选一个，把它同时作用于所有数字，然后选择清除个位、十位或百位区间中的一组数字。
- **[源码观察]** 桌面为 7×8 共 56 个数；合法范围 1–999，运算后越界值变为 0/出界。选中的运算会被消费，并从洗牌牌库补充。
- **[源码观察]** 循环为“读全局分布 → 比较三个运算的整体后果 → 承担一部分越界损失 → 选择一个数量级清除 → 得分并补牌/补数”。
- **[设计推断·高]** 每个动作作用于全部对象，局部收益无法与全局损失分离；乐趣来自管理分布而非计算单个答案。

### 状态、奖励与内容

- **[源码观察]** 使用显式状态表和动画系统，运行于 `_update60()`；主要对象是数字格、运算牌、数量级选择和过渡动画。
- **[源码观察]** 得分为清除数量 × 数量级权重（个位 4、十位 3、百位 2）× 奖励倍率；全清且无越界可获 3 倍，目标区间与越界合计覆盖全桌可获 2 倍。
- **[源码观察]** 特定轮次重新补数，间隔逐渐增长；少于 5 个格子时结束。
- **[设计推断·中]** 越界既是损失又能参与某些清盘倍率，形成“可控牺牲”而非纯错误。

### 难度、反馈与重试

- **[源码观察]** 难度来自可操作数字减少、补数节奏、随机运算手牌和跨数量级分布，而非实时压力。
- **[源码观察]** 动画把全局运算、越界、清除和倍率结算分阶段展示，使大规模状态变化仍可读。
- **[源码观察]** 少于阈值后进入结算并重新开局；分数支持长期比较。

### 代码结构与关键关系

- **[源码观察]** 状态机控制选择运算、变换、选择数量级、清除、计分、补充和结束；数据表保存运算定义、牌库、数字及动画任务。
- **[源码观察]** 关键调用链是“选择操作 → 对全表应用 → 分类到三个数量级/越界 → 选择清除 → 计算倍率 → 安排补数/结束”。

### 机制作用

- **[设计推断·高]** 全局动作产生可预测但无法局部隔离的副作用；倍率把一部分越界损失转化为可控牺牲；分阶段动画让大范围状态变化仍可理解。

## 6. Solid Rogue

**来源**：[官方 BBS 页面](https://www.lexaloffle.com/bbs/?pid=90517)；作者 grimmrobe；卡带 `solidrogue-3`；回合制潜行 Roguelike；CC BY-NC-SA 4.0。

### 玩法与循环

- **[事实]** 玩家尝试穿过 20 层程序生成的潜行关卡，避免或暂时击倒守卫。
- **[源码观察]** 四向移动一格会推进敌方回合；X 可等待；按住 Z 加方向可向前窥视，同方向继续操作可冲刺两格并消耗体力。
- **[源码观察]** 循环为“窥视获取视野/敌情 → 判断噪声和守卫朝向 → 移动、等待或冲刺 → 敌人感知并行动 → 寻找楼梯与资源”。
- **[设计推断·高]** 窥视把不确定性转化为信息，冲刺再把同一输入关系转化为空间收益；体力使情报和行动形成资源权衡。

### 状态、实体与 AI

- **[源码观察]** 玩家每层约 4 点体力、3 点生命（上限 4）；箱子可治疗。撞击守卫可使其昏睡约 15 回合。
- **[源码观察]** 守卫状态包含站立、睡眠、搜索、行走、追猎和狂乱；视线、距离听觉、噪声源与 A* 寻路共同驱动 AI。
- **[源码观察]** 格栅和撞墙等行为会产生噪声；问号、叹号和状态图标让警觉变化可见。
- **[源码观察]** 实体按组件/系统方式组织，地图、视野、AI、路径、回合和渲染各自承担明确职责。

### 生成、难度与重试

- **[源码观察]** 每层由 2×2 象限拼成，每个象限从精灵表中的 16 种 8×8 模板选择；楼梯、玩家、箱子与敌人再随机布置。
- **[源码观察]** 楼层数据调整敌人和箱子配置；20 层构成长局难度。死亡重置整局，持久化最佳楼层和最快通关时间。
- **[设计推断·高]** 模板拼接兼顾作者控制的局部可读性与整局变化；永久死亡让信息和体力决策具有长期重量。

### 代码结构与关键关系

- **[源码观察]** 主循环按“读取玩家意图 → 解析移动/窥视/冲刺 → 生成噪声 → 守卫感知与寻路 → 结算伤害/楼层 → 更新 FOV → 绘制”推进。
- **[源码观察]** 关键关系是 `noise/sight → AI state transition → pathfinding → enemy action`，以及 `peek → information → dash/stamina`。

### 机制作用

- **[设计推断·高]** 同一方向输入从窥视递进到冲刺，在信息与位移之间建立连续关系；回合制把潜行从即时反应变成规划，模板生成兼顾变化与战术可读性，警觉图标则把复杂 AI 状态暴露给玩家。

## 跨样本结论

- **[设计推断·高]** 最强机制都让一个简单动作承担两种以上意义：移动兼攻击、观察兼准备、全局变换兼牺牲、连接兼动量。
- **[设计推断·高]** PICO-8 的限制促使反馈、状态和关卡数据直接服务核心循环；理解样本时，应优先追踪动作如何跨系统产生多样局面，而不是只统计内容量。
